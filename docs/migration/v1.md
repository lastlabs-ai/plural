# Migrate from v0.7 to the v1 foundation

The v1 package/execution foundation is additive and still classified Alpha.
The v0.7 routing, tracing, `Environment` episode API, `TaskDataset`,
`Benchmark`, `Report`, and Studio client remain public. Do not rewrite a working
v0.7 workflow solely to adopt names: migrate when immutable external harnesses,
sandbox providers, durable Trials, receipts, or verifier regrade are useful.

## Concept mapping

- `Environment[Observation, State]` remains the in-process authoring/runtime
  API. `EnvironmentManifest` is the strict package execution contract.
- `TaskData`/`TaskDataset` remain supported by legacy `Benchmark.run`.
  `TaskDefinition` is the v1 manifest record owned by an Environment.
- `Benchmark(..., repeats=N)` remains supported and reports zero-based
  `CaseKey.repeat`. `JobSpec.n_attempts=N` creates one-based independent Trial
  attempts. Both mean independent statistical repetitions, not retries.
- Legacy model strings/policy factories become `AgentSpec` values that also pin
  one Environment identity and one Harness binding.
- Legacy `runtime_factory` is a synchronous tool-call boundary per case. The v1
  `SandboxProvider` owns complete harness/verifier process lifecycle.
- A legacy `Report` remains the aggregate compatibility shape.
  `Job.report(result)` converts v1 Trials into that shape and maps
  `attempt - 1` back to `CaseKey.repeat`.

## Tasks

Convert without exposing evaluator-only values:

```python
from plural import TaskDefinition

definitions = tuple(
    TaskDefinition(
        task_id=task.task_id,
        input=task.input,
        expected=task.expected,
        metadata=task.metadata,
    )
    for task in dataset.tasks
)
```

Keep `TaskDataset` and its sidecar manifest for legacy consumers. The v1
Environment/Benchmark lock uses a different canonical Pydantic model and
`sha256:` digest format; do not expect the old dataset `content_hash` string to
equal `JobLock.task_set_hash`. Preserve task order and stable IDs.

## SDK workflow to SDK/CLI execution

Previously:

```python
report = Benchmark(env, models=[model], client=client, repeats=3).run(dataset=tasks)
client.create(report)
```

In the v1 foundation:

1. Package Environment tasks/instructions/tools/code/policy and verifier.
2. Package the external or built-in Harness and add its exact binding.
3. Create a Benchmark selecting ordered task IDs for that Environment digest.
4. Create one Agent per model/routing setup, each with exactly one Harness.
5. Create a Job with `n_attempts: 3`, choose a provider, dry-run, then execute.
6. Preserve the lock, receipts, artifacts, and result under `.plural/jobs`.

```bash
plural run job.yaml --dry-run
plural run job.yaml --runtime docker
```

The legacy object API and v1 execution graph remain distinct resource models.
Continue using `client.create/update` for legacy Environment/Trace/Benchmark
objects. Use `plural env push` for v1 environment revisions, opt-in
`plural run --sync`, or replay a completed local result with
`plural job upload`.

## Compatibility checklist

- Keep `Benchmark.repeats` until all callers consume `JobSpec.n_attempts`.
- Keep `TaskDataset` files for old runs; generate v1 manifests alongside them.
- Pin Environment and Harness digests; rebuild dependent Benchmark/Agent files
  after changes.
- Start with `--dry-run`, then explicitly trusted local execution, then a
  provider whose controls satisfy production policy.
- Compare converted `Job.report()` output with the old report on an offline
  deterministic policy before moving live traffic.
- Treat receipt `trust: self_reported` and unsigned package digests honestly;
  v1 does not add remote attestation.
